# Эмулятор командной оболочки — вариант 14

Практическая работа по конфигурационному управлению, ИКБО-41-25.
Реализованы этапы 1–5. Интерфейс на Tkinter, заголовок содержит имя VFS.
Требуется Python 3.11+ с Tkinter; сторонние библиотеки для работы и тестов
не нужны. Сборка не требуется.

## Запуск

Linux/macOS:

```sh
sh run.sh run --vfs data/vfs_deep --startup startup/stage4.txt
sh run.sh test
```

Windows:

```bat
run.bat --vfs data/vfs_deep --startup startup/stage4.txt
run.bat test
```

Прямой запуск: `python src/main.py --vfs data/vfs_deep`.
Для тестов напрямую: добавить `src` в `PYTHONPATH`, затем выполнить
`python -m unittest discover -s tests -v`.
В `run.sh` интерпретатор можно задать переменной `PYTHON`.

## Настройки этапа 2

- `--vfs ПУТЬ`: директория-источник VFS на диске.
- `--startup ПУТЬ`: стартовый текстовый скрипт UTF-8.
- `--config ПУТЬ`: конфигурация TOML с `vfs_path` и `startup_path`.

```toml
vfs_path = "data/vfs_deep"
startup_path = "startup/stage4.txt"
```

Значения CLI имеют приоритет над TOML. Относительные физические пути
отсчитываются от рабочего каталога процесса. BAT-файл переходит в папку
проекта. Ошибки TOML сообщаются до запуска окна. При ошибке загрузки VFS
программа сообщает причину и использует пустую VFS.

## VFS и пути

Источник читается один раз в дерево `VfsNode`. Файлы хранятся в `bytes`,
папки содержат словарь детей. Эмулятор работает только с копией в памяти,
не вызывает системные команды и не меняет исходный каталог.

Состояние `Vfs.cwd` общее для скрипта и интерактивного ввода. Пути используют
`/`, абсолютную и относительную форму, `.` и `..`. Выход выше корня
остаётся в `/`. Промежуточные каталоги должны существовать: путь
`missing/../file` не обходит эту проверку. Имена с пробелами заключаются
в кавычки. Путь реального домашнего каталога не появляется в VFS автоматически.

`vfs-info` выводит имя, источник и SHA-256 путей и содержимого текущего
дерева. Хеш считается в сортированном порядке; текущая папка на него не влияет.

Тестовые источники: `data/vfs_minimal` (один файл), `data/vfs_flat`
(несколько файлов и пустой файл), `data/vfs_deep` (четыре уровня).

## Команды этапа 4

| Команда | Режимы |
| --- | --- |
| `ls [ПУТЬ ...]` | Отсортированные непосредственные дети, по умолчанию текущая папка |
| `ls -a`, `ls -l`, `ls -al` | Скрытые имена и точки; тип и размер в байтах; сочетание ключей |
| `cd [КАТАЛОГ]` | Переход в папку, без аргументов — в корень |
| `clear` | Очищает текст окна, сохраняя VFS и текущий каталог |
| `wc ФАЙЛ ...` | Количество LF, слов и байтов; итог для нескольких файлов |
| `wc -l`, `-w`, `-m`, `-c` | LF, слова, символы Unicode, байты; ключи сочетаются |
| `vfs-info` | Имя VFS, источник и SHA-256 |
| `exit` | Закрывает окно |

`ls` и `wc` поддерживают `--`: например, `wc -c -- -filename`.
Длинный `ls` — упрощённый формат: тип `d`/`-`, владелец:группа, размер,
время модификации в наносекундах Unix и имя.
У каталогов размер данных равен нулю. Скрытые элементы начинаются с точки.

`wc` считает строки по байту LF: последняя строка без LF не увеличивает
счётчик строк. Слова разделяются Unicode-пробелами, включая перевод строки.
Режимы `-w` и `-m` требуют UTF-8; `-l` и `-c` допускают бинарные данные.
Счётчики выводятся в порядке строки, слова, символы, байты независимо
от порядка ключей. Без ключей выводятся строки, слова, байты.
Чтение stdin и полный набор опций системных UNIX-утилит не реализованы.
Ошибка операнда прерывает текущую команду; следующий ввод продолжает работу.

## Парсер и стартовые скрипты

`shlex` обрабатывает кавычки; затем `$VAR` и `${VAR}` раскрываются из
окружения ОС. Значение с пробелами остаётся одним аргументом, неизвестная
переменная превращается в пустую строку. Одинарные кавычки пока также
не подавляют раскрытие переменных (ограничение этапа 1).

Скрипты пропускают пустые строки и строки-комментарии `#`. Каждая команда
и результат попадают в протокол. Ошибки помечены номером строки, выполнение
продолжается. `exit` останавливает скрипт и закрывает окно. `clear` очищает
окно при воспроизведении; в stdout остаётся протокол с отметкой очистки.

Демонстрация: `sh scripts/stage4.sh` или `scripts\stage4.bat`.
Сценарий `startup/stage4.txt` показывает все режимы новых команд и намеренные
ошибки. Окно остаётся открытым, чтобы можно было просмотреть результат.
Для ручной проверки очистки введи `clear`, затем `ls`.

Скрипты этапов 2–3 сохранены в `scripts/stage2_*.sh` и `scripts/stage3_*.sh`.
Прежние сценарии теперь вызывают реальные `ls` и `cd`, поэтому отсутствующие
пути дают сообщения об ошибках вместо вывода заглушки.

## Устройство и функции

- `src/config.py`: `build_parser`, `read_config_file`, `pick_value`,
  `load_config`, `describe` — проверка и объединение CLI/TOML.
- `src/vfs.py`: `VfsNode`, `Vfs`; `empty_vfs`, `load_vfs`, `read_directory`
  создают дерево; `walk`, `format_path`, `vfs_hash`, `describe_source`
  обходят и описывают его.
- `src/paths.py`: `node_at` получает проверенный узел, `require_directory`
  проверяет тип, `step` обрабатывает компонент, `resolve` разрешает путь.
- `src/commands.py`: `parse_options`; `change_directory`; `list_entries`,
  `format_entry`, `list_directory`; `count_file`, `format_counts`,
  `word_count` реализуют команды и их форматирование.
- `src/mutations.py`: `touch_target` находит или создаёт узел; `touch` и
  `update_times` обновляют время; `parse_identity` разбирает владельца и группу;
  `set_ownership` и `chown` изменяют метаданные в памяти.
- `src/emulator.py`: `expand_vars`, `parse_line`, `has_invalid_args`,
  `execute_line`, `run_handler`, `format_vfs_info`, `run_script`,
  `run_script_line` — парсер, выполнение и протокол. `format_stub`
  сохранён для совместимости с тестами первого этапа.
- `src/main.py`: `App` отображает команды и результаты; `on_enter`,
  `run_command`, `replay` обрабатывают ввод, очистку и скрипт;
  `prepare_vfs`, `mirror`, `main` организуют запуск и дублирование вывода.

Настройки кода: `MAX_ARGS` ограничивает аргументы, `COMMANDS` содержит
обработчики, `WC_ORDER`/`WC_DEFAULT` задают счётчики, `SINGLE_OPERAND`
определяет порог вывода заголовков и итогов. Размер окна, шрифт и цвета
заданы константами `src/main.py`. Оформление проверяется `ruff.toml`.

## Проверки

`run.bat test` или `sh run.sh test` запускают все тесты без окна.
Проверяются настройки, загрузка VFS, пути, команды, Unicode/бинарные данные,
скрипты и ошибки. Правила кода: `ruff check src tests` (Ruff нужен только
разработчику). Функции должны иметь сложность не выше 10, длину не более
40 строк, а строки Python — не более 80 символов.

## Команды этапа 5

| Команда | Режимы |
| --- | --- |
| `touch ПУТЬ ...` | Создаёт пустые файлы или обновляет метки времени |
| `touch -a`, `-m`, `-am` | Время доступа; время изменения; обе метки |
| `touch -c ПУТЬ ...` | Не создаёт отсутствующий файл, обновляет существующий |
| `chown OWNER ПУТЬ ...` | Меняет только виртуального владельца |
| `chown OWNER:GROUP ПУТЬ ...` | Меняет владельца и группу |
| `chown :GROUP ПУТЬ ...` | Меняет только группу |
| `chown -R OWNER:GROUP КАТАЛОГ ...` | Меняет поддерево, включая скрытые файлы |

Обе команды принимают несколько путей и разделитель `--`. Родитель нового
файла должен существовать. `touch` никогда не обнуляет содержимое имеющегося
файла; допускается обновление временных меток существующего каталога.
По умолчанию меняются обе метки. Ключи `-a`, `-m`, `-c` сочетаются.

Владельцы и группы — строки внутри VFS: имена из букв, цифр, `_`, `.`, `-`
или числовые идентификаторы. Они не ищутся в учётных записях ОС, права
администратора не нужны. Пустая спецификация, `OWNER:` и несколько двоеточий
отклоняются. Ключи `chown` задаются до `--`; после него идут операнды.

Начальные виртуальные владелец и группа: `user` и `users`; метки времени
инициализируются при загрузке узла. Права доступа и реальные владельцы
источника не моделируются. Режимы `touch -t/-r`, параметры ссылок и полный
набор ключей системных утилит не реализованы.

`ls -l` показывает результат `chown` и время изменения после `touch`.
SHA-256 команды `vfs-info` учитывает пути и байты: создание файла меняет хеш,
но изменение только владельца или временных меток его не меняет.
При закрытии окна все изменения теряются, исходные файлы на диске остаются
прежними. Повторный запуск загружает первоначальный каталог.

Демонстрация: `sh scripts/stage5.sh` или `scripts\stage5.bat`.
Прямой запуск:
`python src/main.py --vfs data/vfs_deep --startup startup/stage5.txt`.
Сценарий показывает все перечисленные режимы и обработку ошибок, оставляя
окно открытым для просмотра. Этап 4 демонстрируется своим отдельным скриптом.

`CHOWN_MIN_OPERANDS` задаёт минимальное число аргументов; `IDENTITY_PATTERN`
проверяет имена. `DEFAULT_OWNER` и `DEFAULT_GROUP` задают начальные значения.
