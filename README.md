# Эмулятор командной оболочки ОС

Учебный проект по дисциплине «Конфигурационное управление»,
вариант №14, группа ИКБО-41-25, РТУ МИРЭА.

## Общее описание

Приложение имитирует работу в командной строке UNIX-подобной ОС.
Интерфейс графический, на `tkinter`: одно текстовое поле работает и на
ввод, и на вывод. Так получается диалог с пользователем. Заголовок окна
содержит имя VFS.

Сделаны **Этап 1 «REPL»**, **Этап 2 «Конфигурация»** и **Этап 3 «VFS»**.
Команды `ls` и `cd` пока заглушки: выводят своё имя и аргументы, их
логика относится к Этапу 4. Работают разбор строки, раскрытие
переменных окружения, параметры командной строки, конфигурационный
файл, стартовые скрипты и загрузка VFS со служебной командой `vfs-info`.

Код разложен по четырём модулям: `src/config.py` отвечает за параметры
запуска, `src/vfs.py` за виртуальную файловую систему, `src/emulator.py`
за разбор строки и выполнение команд, `src/main.py` за графический
интерфейс. Только последний импортирует `tkinter`, поэтому тесты
не требуют графического окружения.

## Виртуальная файловая система

Источником VFS является директория на диске пользователя. Она читается
один раз при запуске и целиком помещается в память.

**На диске эмулятор ничего не изменяет.** Данные VFS не распаковываются
и не модифицируются, узлы дерева живут только в оперативной памяти.
Скрипт `scripts/stage3_errors.sh` проверяет это явно: считает
контрольную сумму каталога `data/` до и после прогона и падает, если
она изменилась.

Варианты VFS для проверки лежат в `data/`:

| Каталог | Состав |
| --- | --- |
| `data/vfs_minimal` | Минимальный: один файл |
| `data/vfs_flat` | Четыре файла в корне, включая пустой |
| `data/vfs_deep` | Четыре уровня вложенности, 10 каталогов и 8 файлов |

Если путь к VFS не задан или источник недоступен, эмулятор сообщает
об этом в отладочном выводе и продолжает работу с пустой VFS.

### Команда `vfs-info`

Служебная команда выводит имя VFS, путь к источнику и хеш SHA-256
её данных:

```
$ vfs-info
имя VFS: vfs_deep
источник: data/vfs_deep
SHA-256: d691772a8464bad24819deb493dfe2d656a8b8f07e55b1cd68e87d3f37a916fc
```

Хеш считается обходом дерева в отсортированном по именам порядке,
в него подмешиваются и путь узла, и содержимое файла. Сортировка важна:
без неё результат зависел бы от порядка обхода файловой системы
и менялся бы между запусками.

## Параметры командной строки

| Параметр | Назначение |
| --- | --- |
| `--vfs ПУТЬ` | Путь к физическому расположению VFS |
| `--startup ПУТЬ` | Путь к стартовому скрипту эмулятора |
| `--config ПУТЬ` | Путь к конфигурационному файлу TOML |

При запуске эмулятор печатает отладочный вывод всех заданных
параметров, указывая источник каждого значения:

```
Параметры запуска:
  конфигурационный файл: config/default.toml
  путь к VFS: data/vfs_flat [командная строка]
  стартовый скрипт: startup/stage3.txt [конфигурационный файл]
VFS «vfs_flat» загружена в память.
```

Вывод идёт и в окно, и в стандартный поток, чтобы его можно было
перенаправить в файл.

## Конфигурационный файл

Формат TOML, два ключа:

```toml
vfs_path = "data/vfs_deep"
startup_path = "startup/stage3.txt"
```

**Приоритет:** значение из командной строки важнее значения из файла.
Если параметр задан в обоих местах, берётся тот, что из строки.

Недоступный файл, повреждённый TOML и неизвестный ключ дают сообщение
об ошибке и код возврата 1. Примеры лежат в `config/`: рабочие
`default.toml` и `vfs_only.toml`, а также заведомо испорченные
`broken.toml` и `unknown_key.toml`.

## Стартовый скрипт

Текстовый файл с командами эмулятора, по одной на строку. Пустые строки
и строки, начинающиеся с решётки, пропускаются.

Команды выполняются последовательно. **Ошибочная строка пропускается:**
в окно выводится сообщение с её номером, выполнение продолжается
со следующей команды. На экране видно и ввод, и вывод, так что
получается тот же диалог, что и при ручной работе. Ввод подсвечивается
синим, ошибки красным.

Если скрипт заканчивается командой `exit`, окно закрывается. Иначе
эмулятор переходит в интерактивный режим.

Примеры в `startup/`: `stage3.txt` со всеми командами всех этапов,
`stage2.txt` без работы с VFS, `errors.txt` только из ошибочных строк,
`interactive.txt` без `exit`.

## Функции

### `src/config.py`

| Функция | Назначение |
| --- | --- |
| `build_parser()` | Описывает параметры командной строки |
| `read_config_file(path)` | Читает и проверяет файл TOML |
| `pick_value(cli, file)` | Реализует приоритет командной строки |
| `load_config(argv)` | Собирает итоговую конфигурацию |
| `describe(config)` | Формирует отладочный вывод параметров |

### `src/vfs.py`

| Функция | Назначение |
| --- | --- |
| `load_vfs(path)` | Загружает директорию с диска в память |
| `empty_vfs(name)` | Создаёт пустую VFS, если источник не задан |
| `read_directory(path)` | Рекурсивно читает каталог в узел дерева |
| `walk(node)` | Обходит дерево в устойчивом порядке |
| `vfs_hash(vfs)` | Считает SHA-256 по данным VFS |
| `format_path(segments)` | Собирает текстовый путь из сегментов |
| `describe_source(vfs)` | Представляет источник для служебного вывода |

### `src/emulator.py`

| Функция | Назначение |
| --- | --- |
| `expand_vars(token)` | Раскрывает `$VAR` и `${VAR}` |
| `parse_line(line)` | Разбивает строку на токены и раскрывает переменные |
| `has_invalid_args(name, args)` | Проверяет допустимое число аргументов |
| `format_stub(name, args)` | Формирует вывод команды-заглушки |
| `format_vfs_info(vfs)` | Формирует ответ команды `vfs-info` |
| `execute_line(vfs, line)` | Выполняет одну команду |
| `run_script(vfs, path)` | Выполняет стартовый скрипт, возвращая протокол |

### `src/main.py`

| Элемент | Назначение |
| --- | --- |
| `App` | Окно эмулятора, наследник `tk.Tk` |
| `App.on_enter(event)` | Обрабатывает нажатие Enter |
| `App.replay(events)` | Отображает протокол стартового скрипта |
| `prepare_vfs(config, report)` | Загружает VFS и дополняет отладочный вывод |
| `main(argv)` | Точка входа |

Разбор строки идёт в два шага: `shlex` разбивает её на токены с учётом
кавычек, затем в каждом токене раскрываются переменные окружения.
Раскрытие идёт именно **после** разбиения, поэтому значение
с пробелами остаётся одним аргументом, как в настоящей оболочке.
Неизвестная переменная раскрывается в пустую строку, как в `bash`.

## Команды

| Команда | Этап | Поведение |
| --- | --- | --- |
| `ls [аргументы]` | 1 | Заглушка: выводит своё имя и аргументы |
| `cd [путь]` | 1 | Заглушка: выводит имя и путь, не более одного |
| `vfs-info` | 3 | Имя VFS, источник и SHA-256, аргументов не принимает |
| `exit` | 1 | Завершает работу, аргументов не принимает |

Сообщения об ошибках: `незакрытая кавычка`,
`неверные аргументы команды <имя>`, `неизвестная команда: <имя>`.
В скрипте к ним добавляется номер строки.

## Сборка и запуск

Сборка не требуется. Нужен **Python 3.11 или новее** из-за `tomllib`,
который появился в стандартной библиотеке именно в 3.11, и поддержка
`tkinter`.

Проверка окружения:

```sh
python3 --version
python3 -c "import tkinter, tomllib"
```

Запуск:

```sh
./run.sh                                      # без параметров
./run.sh run --config config/default.toml     # всё из конфигурации
./run.sh run --vfs data/vfs_deep --startup startup/stage3.txt
./run.sh test                                 # тесты
```

Интерпретатор переопределяется переменной `PYTHON`:

```sh
PYTHON=/opt/homebrew/bin/python3.14 ./run.sh
```

Если `tkinter` не найден, поставьте его: `brew install python-tk@3.14`.

## Примеры использования

Служебная информация о загруженной VFS:

```
$ vfs-info
имя VFS: vfs_flat
источник: data/vfs_flat
SHA-256: 76f743756af24c9eddc2ee119970153a6f2670cbd3ec6b2cd887ccf123458504
```

Команды-заглушки и кавычки:

```
$ ls
ls
$ ls -l /home
ls -l /home
$ cd "my folder"
cd my folder
```

Раскрытие переменных окружения:

```
$ cd $HOME
cd /Users/user
$ ls ${HOME}/Documents
ls /Users/user/Documents
```

Обработка ошибок:

```
$ cd "unclosed
Ошибка: незакрытая кавычка
$ cd /home /tmp
Ошибка: неверные аргументы команды cd
$ vfs-info лишний
Ошибка: неверные аргументы команды vfs-info
$ pwd
Ошибка: неизвестная команда: pwd
```

Выполнение стартового скрипта, ошибочные строки пропущены:

```
$ vfs-info
имя VFS: vfs_deep
источник: data/vfs_deep
SHA-256: d691772a8464bad24819deb493dfe2d656a8b8f07e55b1cd68e87d3f37a916fc
$ cd "незакрытая кавычка
Ошибка: ошибка в строке 23: незакрытая кавычка
$ pwd
Ошибка: ошибка в строке 26: неизвестная команда: pwd
$ exit
```

## Известные ограничения

Одинарные кавычки не подавляют раскрытие переменных, в отличие
от `bash`.
